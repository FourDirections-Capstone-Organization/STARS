5. Cloud Infrastructure Hardening vs Code Optimizations

Direct Impact of Applied Azure Cloud Settings
  • Always On: Completely eliminated the 10-30s container idle cold start latency.
  • 64-bit Kestrel Runtime: Removed the 32-bit threadpool cap, enabling the system to sustain 50 concurrent authentications (96.17 req/s, 0 errors) without crashing.
  • HTTP/2.0 Multiplexing: Enabled lightweight read throughput to accelerate from 5.3 to 257.27 req/s and Task Guard to 180.94 req/s over single persistent TCP connections.
  • PostgreSQL max_connections = 100: Doubled database connection headroom, eliminating the 50% timeout failure previously seen at 50 concurrent DB queries.
Code-Level Optimizations Awaiting Deployment (Committed Locally)
  • In-Memory Health Cache: Step 4 wraps /api/health in a 10s memory cache, preventing traffic bursts from querying the live DB on every probe.
  • Rate Limiter Middleware: Step 5 shields /api/auth/login with a 30 req/min sliding window, returning HTTP 429 rather than starving CPU cores under brute-force attacks.
  • Asynchronous DMS Webhook Queue: Step 6 decouples synchronous delivery writes into a Channel queue, converting the 19-second legacy handler into an immediate 202 Accepted response.
